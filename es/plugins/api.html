API reference

Generated from @arkenda/kit/plugin-api (to be published as @arkenda/plugin-api) and its JSDoc. API version 1.2: ctx.apiVersion is 1, ctx.apiMinor is 2.

  • Every ctx call is asynchronous and answered only when the manifest declares its permission, the user granted it, and any contribution id is declared. A refused call rejects with an error whose code says why (error codes).
  • Registrations return a handle (Disposable, or SandboxViewHandle for views); everything is disposed anyway when the plugin is turned off.

The plugin context (ctx)

What activate(ctx) receives in the sandbox (SandboxPluginContext), one section per area. The text of each area names the permission it needs.

ctx.apiVersion

apiVersion: 1;

ctx.apiMinor

The additions this host supports (PLUGIN_API_MINOR).

apiMinor: number;

ctx.manifest

readonly id: string;
readonly name: string;
readonly version: string;
readonly permissions: readonly string[];

ctx.commands

commands — a command's title and default hotkey come from contributes.commands (the hotkey is bound only when free and not reserved; the app's and the user's keys win).

register(command: { readonly id: string; run(): void | Promise<void> }): Promise<Disposable>;

ctx.editor

registerInsertItem and registerToolbarItem need editor and take their titles from contributes.insertItems / contributes.toolbarItems. Data only: text up to 4 KB, an icon of PLUGIN_EDITOR_ICONS, or one of this plugin's commands; an insert item may also name its group (PLUGIN_INSERT_GROUPS), search keywords and a detail shown next to its title in the / menu.

registerInsertItem(item: {
  readonly id: string;
  /** At most 120 characters. */
  readonly detail?: string;
  readonly text: string;
  readonly cursor?: number;
  readonly icon?: PluginEditorIcon;
  /** The insert menus' group; `plugins` when not given. */
  readonly group?: PluginInsertGroup;
  /** Up to 8 extra filter words of at most 32 characters. */
  readonly keywords?: readonly string[];
}): Promise<Disposable>;
registerToolbarItem(
  item: { readonly id: string; readonly icon: PluginEditorIcon } & (
    | { readonly text: string; readonly cursor?: number }
    | { readonly command: string }
  ),
): Promise<Disposable>;

ctx.appearance

ui:themes — a theme of token values only (THEME_TOKENS: colours, quoted font stacks, radii, line heights), its label from contributes.themes. No CSS: anything outside the token grammar, or text below 4.5:1 on the background, is refused with invalid-params.

registerTheme(theme: {
  readonly id: string;
  readonly mode: PluginThemeMode;
  readonly tokens: ThemeTokens;
  readonly darkTokens?: ThemeTokens;
}): Promise<Disposable>;

ctx.markdown

markdown — renders fenced code blocks of the language id (```<id>). The returned HTML is sanitized and hardened by the app (no scripts, styles, frames, forms or remote images).

registerCodeBlock(block: {
  readonly id: string;
  render(source: string): string | Promise<string>;
}): Promise<Disposable>;

ctx.views

ui:panels. icon sets its tab icon, places (distinct left, right, status) where people may move it and defaultPlace (one of them) where it shows by default; the manifest's contributes.sidebarPanels values win when it declares them. Anything else (an icon outside PLUGIN_PANEL_ICONS, say) is refused with invalid-params.

registerSidebarPanel(
  panel: SandboxViewRegistration & {
    readonly icon?: PluginPanelIcon;
    readonly places?: readonly PluginToolPlace[];
    readonly defaultPlace?: PluginToolPlace;
  },
): Promise<SandboxViewHandle>;

ctx.settings

registerTab needs ui:panels; registerFields and values need storage (the values are kept there). Fields are rendered by the app; onChange gets the values after every change. A settings schema too (groups, more types, scopes, migrations). A sandboxed plugin reads only its own values, never secrets (a secret field is entered and kept by the app alone).

registerTab(tab: SandboxViewRegistration): Promise<SandboxViewHandle>;
registerFields(
  schema: PluginSettingsSchemaInput,
  onChange?: (values: PluginSettingValues) => void,
): Promise<Disposable>;
values(): Promise<PluginSettingValues>;
/**
 * Changes one of its own settings, checked as if the user entered it (an unknown key, a
 * secret or a refused value is refused with `invalid-params`); `onChange` follows.
 */
set(key: string, value: PluginSettingValue): Promise<void>;

ctx.permissions

No permission needed: what the user granted it on this device right now (it can change at any time): the granted permissions, the approved hosts, and whether it sees every note, only chosen notebooks and tags, or none. A plugin keeps working without its optional permissions.

granted(): Promise<{
  readonly permissions: readonly string[];
  readonly hosts: readonly string[];
  readonly notes: 'all' | 'chosen' | 'none';
}>;

registerWidget(

ctx.sync

sync (API 1.1; check ctx.apiMinor >= 1), for plugins of the syncing category: offers a sync source declared in contributes.syncSources (its title comes from there). The user adds it per vault in Settings ▸ Sync & devices, and pauses or removes it there; the app then calls onControl with start, stop, sync (one pass: "Sync now", the app opened or came back) or remove (forget what you kept for this vault). On phones, sync only on start and sync: nothing runs in the background. The source contacts only the manifest's network.hosts the user approved, and reads or changes notes only through notes and its scope: registering it grants nothing. Control calls stop at once when the user revokes sync. Present only when the manifest declares sync.

registerSource(source: {
  readonly id: string;
  /** What it needs from the user, shown before it is added: `account`, `keys`, `folder`. */
  readonly needs?: readonly PluginSyncSourceNeed[];
  onControl(action: PluginSyncSourceAction): void | Promise<void>;
}): Promise<{
  /** Shown under the source: `idle`, `syncing` or `error`, a line of at most 160 characters, the last pass. */
  setStatus(status: {
    readonly state: PluginSyncSourceState;
    readonly detail?: string;
    readonly lastSyncAt?: number;
  }): Promise<void>;
  dispose(): void;
}>;

ctx.notifications

notifications — shown in the status bar; same user-action rule as the clipboard.

show(notification: { readonly title: string; readonly body?: string }): Promise<void>;

ctx.network

network — a GET the app makes for the plugin, only to a host of network.hosts the user approved (host-not-allowed otherwise; network-not-available while none is). Desktop app only: on the web and phones it always answers network-not-available. https only, no cookies or credentials, redirects re-checked, no private or local address, 5 s and 256 KB at most. Fails with network-failed.

fetch(url: string): Promise<{
  readonly status: number;
  readonly contentType: string | null;
  /** The body as UTF-8 text. */
  readonly body: string;
  /** The link that answered, after redirects. */
  readonly url: string;
}>;
